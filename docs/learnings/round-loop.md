# Round-loop journeys

JN3's idle-cue scenario must begin with actual fresh manual input. Startup renderer
work or a tutorial can already trigger dropout/autopilot; an already-dropped seat
does not earn a new idle cue until deliberate input hands it back. Apply input via
the real controller, observe manual/fresh state, then neutralise before timing the
idle warning. Keep the natural lap and original deadlines. See br-ncvu's failing
state and passing journey receipt.

Run latency-sensitive host journeys serially on software WebGL: a simultaneous
24-view host can delay Identify beyond its existing deadline. A successful isolated
run proves that journey; it does not qualify hardware latency or the large cohort.
